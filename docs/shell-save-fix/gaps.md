# shell-save-fix gap hunt

Branch `shell-save-fix` (edd057d99e) compared with dev (ff4a652d1b, via `.worktrees/dev-baseline`, same parse.ts blob).
Every row was run through the real `ShellParse.scan`. "Covers" means each resource of the other command matches one of the saved patterns under `Wildcard.match`.
Probe: `probe/p.ts`; cases `probe/c1.txt`..`probe/c8.txt`. `p.ts` compares two checkouts: set `B` (this branch) and `D` (origin/dev) at its top, and the `effect` import, to local paths.
Run it with `bun probe/p.ts probe/cN.txt` (add `SH=/usr/bin/pwsh` for PowerShell). Line format: `approved ||| other ||| other`: the save from the first command is tested against the others.

Line references are to `packages/core/src/shell/parse.ts` on the branch.

## Known items (confirmed)

- Unmodelled wrappers: `pkexec rm x` saves `pkexec *` on both branch and dev, and it covers `pkexec bash`. The same happens with `unshare *`, `nsenter *`, `taskset *` and `script *`.
- Plain saves with backslashes: `\git push` saves `\git *` on both, and it covers `/git push`. `git a\ b` saves `git a\ b *`, which covers `git a/ b`. `FOO=1 git a\ b` saves `FOO=1 git a\ b *` and stays savable, because the check at :300 only applies when `inner !== undefined`.

## Fix plan (ranked by severity)

1. **Non-static words (W3).** A single check at :297 marks a command unsavable when the literal part of its save holds `$` or a backtick outside single quotes. This closes free redefinition through assignment segments for plain and wrapper saves.
2. **Stdin-fed code (W1, W2).** In `wrapped()` (:680, :686), a shell or interpreter with no script operand (or with `-s` or `-`), and xargs running a shell or script runner, return an "unsavable" sentinel. At :297, set `output.unsavable` for it.
3. **Find always exact (W5).** One-line change at :676: `return null` for every `find`. If that breaks the test for `find . -name x` saving `find *`, update the test; it encodes the widening.
4. **Options inside the arity span (W4, W9, W11).** In `prefix()` (:662), stop at the first `-` or `+` token after the program, look up arity with unquoted `item.words`, and when the prefix is cut by an option or redirect, save `item.resource` exactly.
5. **Interpreters and `source` (W6, W7).** Extend SHELLS (:198) with `python`, `python3`, `node`, `perl`, `ruby`, `bun`, `deno`, `fish`, `csh`, `tcsh`, `nu`, `pwsh`, `powershell`, `cmd`, `source` and `.`, and drop `source: 1` from ARITY (:47). Add `parallel` to SCRIPT_RUNNERS (:197) and package runners (`uv run`, `uvx`, `bunx`, `pipx run`, `bundle exec`, `poetry run`) to WRAPPERS or ARITY. For PowerShell, add an exact or unsavable list for `Invoke-Expression`, `iex`, `Start-Process`, `sudo` and `timeout` near :290.
6. **Redirect-only saves (W10).** At :224, save `item.resource` instead of `${head}${separator}*`.
7. **Exec-capable options (W8).** Add a table of commands that save exactly (`awk`, `sed`, `rg`, `fd`, `tar`, `ssh`), and git subcommands with exec options (`fetch`, `clone`, `push`, `rebase`, `submodule`) either exact or option-gated. Larger scope; it may belong in a follow-up PR.
8. **Usability (U1-U3).** Treat `command -v` as a lookup. Self-match the bash `conventional` save with an exact fallback. Build `narrow` from source offsets.
